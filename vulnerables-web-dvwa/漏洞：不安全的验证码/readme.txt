访问地址：`https://xxx/vulnerabilities/captcha/`

>
> **漏洞类型：业务逻辑漏洞**，不是注入、不是文件包含，是**验证码校验逻辑设计缺陷，攻击者可以绕过验证码直接修改密码**CSDN博...。

业务场景：修改密码页面，设计上要求：

1. step=1：填写新密码 + 输入谷歌 reCAPTCHA 人机验证码；
2. 验证码校验成功，才进入 step=2；
3. step=2：提交表单，真正修改数据库密码。

>
> 预期：必须答对验证码，才允许改密码。
> 漏洞点：**step 是客户端可控的 POST 参数，服务器没有在服务端会话记录 “验证码是否已经通过”，攻击者可以直接跳到第二步，跳过验证码校验直接改密码**
