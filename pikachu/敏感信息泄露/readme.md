> 页面：`vul/infoleak/findabc.php`，页面是登录框，提示 “找找看，很多地方都有风险”。

## 方法 1：查看网页源代码拿到账号密码（标准解法）

1. 在登录页面，鼠标右键 → **查看网页源代码**（快捷键 `Ctrl+U`）。
2. 滚动到页面底部，能看到 HTML 注释，注释里面写了测试账号密码：

```
<!-- 测试账号:lili/123456 -->
```

> 
> HTML 注释浏览器不显示，但访问者查看源码就可以直接读到，属于**前端源码敏感信息泄露**。

3. 使用账号：`lili`，密码：`123456`，点 Login 登录成功，进入`abc.php`内容页。

## 方法 2：直接访问后端页面绕过登录（另一种利用方式）

观察 URL：`findabc.php`，真正内容页面是`abc.php`，**abc.php 没有做登录校验**，直接修改浏览器地址访问：

```
https://f0012fbf98204f57ae3bbf2cb76c8bce--8081.ap-shanghai2.cloudstudio.club/vul/infoleak/abc.php
```

直接打开，不需要登录，看到页面内容，绕过登录框。

## 额外现象：Cookie 信息泄露

登录成功后，打开浏览器 F12 开发者工具 → 网络，刷新页面，看 Cookie：
Cookie 里面存放了用户名，还有 MD5 加密后的密码，敏感信息放在 Cookie 中泄露。CSDN博...

## 漏洞原理

1. **HTML 注释泄露敏感凭据**：开发调试留下账号密码写在页面注释，部署上线忘记删除，任何人看源码就拿到账号密码。
2. **后端页面缺少鉴权**：真正业务页面`abc.php`没有登录判断，可以直接访问绕过登录界面。
3. Cookie 存放敏感加密密码，存在被窃取破解风险。

## 修复方案

1. 上线前清理 HTML、JS 注释，删除调试账号密码、接口地址、内网信息；
2. 对业务页面`abc.php`增加 session 登录校验，禁止未授权直接访问；
3. Cookie 不要存放密码（哪怕是密文）；敏感页面后端强制鉴权，不能只靠前端登录表单做访问控制。
